### 如何发现何时应该使用 Backtracking（回溯）？

回溯法本质上是一种 ** 有规律的、带剪枝的深度优先搜索（DFS） ** 。当遇到以下特征的问题时，通常应该优先考虑使用回溯：

#### 1. 问题的提问方式
如果题目中出现以下关键字，大概率需要使用回溯法：
* ** "找出所有可能的组合 / 排列 / 子集" **（Generate
all..., Find
all
combinations / permutations / subsets...）
* ** "找出所有满足条件的解" **（例如
N
皇后、解数独等，需要列出具体摆放方案而不仅仅是一个数量）

#### 2. 决策树（Decision Tree）结构
如果你可以把问题的求解过程画成一棵树：
*在每一个节点，你都需要面临 ** 若干个选择 **（比如这道题中，在每个位置你可以选择放
`(`，也可以放 `)`）。
*做出一个选择后，你将进入下一个子问题。
*如果发现当前的选择无法走向终点（不满足约束），需要退回上一步，重新做别的选择。

#### 3. 数据规模（Constraints）非常小
回溯法的时间复杂度通常是指数级（$O(2 ^ N)$）或阶乘级（$O(N!)$）。因此，如果题目给出的数据范围极小，这通常是一个强烈的信号。
*例如：$N \le
10$（排列问题 $10! \approx
3.6 \times
10 ^ 6$）
*例如：$N \le
20$（子集问题 $2 ^ {20} \approx
10 ^ 6$）
*本题中 $N \le
8$（括号组合最大长度为
16），说明可以直接使用回溯搜索所有情况。

### 使用回溯时应该注意什么？

写回溯算法时，可以遵循一个通用的经典模板，并注意以下四个核心要素：

#### 经典回溯模板：
```python


def backtrack(路径, 选择列表):
    if 满足结束条件:
        res.append(路径的副本)
        return

    for 选择 in 选择列表:
        if 剪枝条件(不满足约束):
            continue

        做选择(更新路径和状态)
        backtrack(路径, 选择列表)
        撤销选择(恢复路径和状态)


```

在具体实现中，需要特别注意以下几点：

#### 1. 必须正确“撤销选择”（恢复状态）
这是回溯法最容易出错的地方。我们在进入下一层递归前修改了全局状态或共享的路径变量（例如
`path.append('(')`），在递归返回后， ** 必须将状态恢复到调用前的样子 **（例如
`path.pop()`）。如果漏掉这一步，污染了状态，后续其他分支的计算就会全部出错。

#### 2. 结果收集时的“深拷贝”问题
在许多语言中（包括
Python、Java），列表 / 数组是引用传递。
*如果你在结束条件处直接写
`res.append(path)`，最终
`res`
里面存储的将全部是指向同一个
`path`
对象的引用。当回溯结束
`path`
被清空后，你得到的结果列表里将全是空列表。
* ** 解决方法 **：在放入结果集时进行深拷贝（拷贝当前状态的值）。在
Python
中，可以使用
`res.append(path[:])`
或
`res.append(list(path))`。对于括号生成这道题，`"".join(path)`
会创建一个全新的字符串，因此隐式地完成了拷贝。

#### 3. 剪枝（Pruning）至关重要
如果不加限制地生成所有括号，长度为 $2
n$ 的括号序列一共有 $2 ^ {2
n}$ 种可能。如果 $n = 8$，就是 $2 ^ {16} = 65, 536$ 种。
*通过剪枝条件
`open_count < n`
和
`close_count < open_count`，我们只在能生成合法括号的分支上继续往下走，无效的分支在刚露头时就被砍掉了。
* ** 设计合理的剪枝条件 ** 是降低回溯算法时间复杂度的关键。

#### 4. 明确递归出口（Base Case）
必须要清晰地定义什么情况下算“走到了终点”。如果出口条件写错，可能会导致无限递归或漏掉正确的解。通常出口条件是“路径长度达到了目标值”或“可用的选择列表为空”。
